## Goal

Click **2D Goal Pose** in RViz and watch the rover plan a path around the
furniture and drive there on its own.

This is the payoff issue. It is also the first time the robot moves without a
human holding a button, so every safety layer from issue 06 must be verified
first.

## What you will learn

- The split between **planner** (draws the path) and **controller** (turns the
  path into wheel speeds, moment to moment) — and why they're separate
- What **MPPI** does: samples many possible short-term futures, scores them, and
  picks the best. Not following a line — continuously re-deciding.
- What a **behavior tree** is, and why this one deliberately has **no blind
  Spin/BackUp recoveries** (a tethered rover reversing blindly is how you break
  a cable or a wall)
- **Lifecycle nodes**: nav2 nodes must be explicitly *activated*. "Running but
  not active" is a real state and a common source of confusion.

## Known state going in

- nav2 is built and configured: planner + MPPI + a deliberately safe BT
  (`config/nav2.yaml`, `config/bt_navigate_to_pose.xml`).
- Speed caps: MPPI `vx_max 0.30` / `wz_max 1.0`; velocity_smoother `0.25 / 1.0`.
- **The full command chain — nothing may bypass it:**
  ```
  controller_server → /cmd_vel_nav → velocity_smoother → /cmd_vel_smoothed
    → collision_monitor → /cmd_vel_shim → safety_guard → /cmd_vel → ESP32
  ```
  `cmd_vel_nav` is *also* the velocity_smoother's input, so the collision monitor
  must **not** publish there — doing so once created a feedback loop *and*
  bypassed the monitor at the same time.
- `./run_stack.sh vision` must be running before nav2 drives — it starts
  `depth_to_cloud.py`, and with no fresh obstacle source the collision monitor
  fail-safes to zero.
- `cmd_vel_deadband.py` was **removed** (2026-08-10) and must not come back: it
  re-floored every command to vx ≥ 0.20 / wz ≥ 0.80, leaving MPPI no fine control
  authority, so the rover weaved and spun instead of tracking the path.

> ⚠️ **CPU is a safety property.** The full stack (SLAM + nvblox + nav2 + YOLO)
> already sits near load ~9 on 6 cores. If the IR rate drops below ~10 Hz,
> cuVSLAM freezes **silently** and the rover keeps navigating on a frozen pose.
> Check `status` before and after starting nav2.
